# Content pillars

## Primary direction

Build around **practical AI decisions proven with real tasks**. News is eligible only when it changes a workflow or decision that can be demonstrated.

## 1. Real-task tool tests — 40%

Test one tool against a defined task, input, success criterion and limitation. Save inputs and outputs. Never claim “I tested” without artifacts.

Examples: document extraction accuracy, coding-agent repair task, research workflow with source verification.

## 2. Workflow builds — 25%

Build a small automation end to end. Show data flow, failure handling, cost/privacy boundaries and what remains manual.

## 3. Model or workflow comparisons — 20%

Use identical inputs and explicit criteria. Label uncontrolled variables. Prefer tradeoffs over winner-takes-all rankings.

## 4. Mechanism explainers — 15%

Explain technical ideas only when they affect a practical choice: context caching, RAG failure modes, local-versus-cloud data flow, agent memory or inference constraints.

## Topic filter

Publish only when the answer to all is yes:

- Is there a concrete viewer decision?
- Can the key claim be sourced or reproduced?
- Is there a visual proof or useful diagram?
- Can the video add original explanation rather than summarize announcements?
- Would the topic still be useful if the hype words were removed?
