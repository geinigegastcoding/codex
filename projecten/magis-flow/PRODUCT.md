# Magis Flow

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated by the user's request to choose and build a new project. Node.js 24.14+, built-in SQLite, plain HTML/CSS/JavaScript; no runtime packages. Build directly in the actual project, as requested; no mock-ups.

## Users

Initial product assumption: Daniël uses this in MagisData process discovery and client conversations. Broader demand is unvalidated.

## Product Purpose

Turn a recurring business process into an editable sequence, transparent time/cost assumptions, explicit human review points, and an exportable implementation brief.

## Operating Context

Dutch language; one local operator; desktop first with usable mobile layout. Existing MagisData and MagisIntel websites remain independent. New project explicitly requested in its own directory.

## Capabilities and Constraints

Create, edit, reorder and persist workflows; three clearly labeled examples; scenario calculator; deterministic analysis; JSON import/export; Markdown implementation brief. No live execution, credentials, customer-data ingestion, mass account creation, or email sending. Existing external websites and DNS are outside this implementation.

## Evidence on Hand

Vault domain strategy and the two public homepages inspected 2026-09-22. The public MagisData service includes process audits, workflow automation and human review. All in-app examples and costs are illustrative, never measured client outcomes.

## Product Principles

- The operator owns every assumption.
- A process plan is clearly distinguished from a running integration.
- Deterministic calculations and rules; AI only belongs in appropriate proposed steps.
- Save errors and conflicts stay visible; no silent overwrite.
- Local data and portable exports.

## Accessibility & Inclusion

Keyboard-operable controls, persistent labels, visible focus, meaningful empty/error states and reduced-motion support.
