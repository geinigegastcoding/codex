**Status:** working evidence worksheet; not a Play Console submission, legal certification, or final policy decision.  
**Latest source review:**20October2026,0.5.0 local source delta. RevenueCat10.28.1 core/UI remains integrated; the earlier offline/no-SDK answers below are historical and must not be filed for this candidate. The 0.5.0 APK has not been accepted.

## Current purchase-service delta — supersedes old no-collection answers

### 20 October local-feature delta

- The 0.5.0 source delta adds up to 30 custom quiz cards (question, answer and two alternatives), a self-described exercise task (up to 120 characters), an optional proximity repetition counter, earned-minute settings, palette/opening greeting (greeting up to 80 characters), and content-filter preferences with up to 100 blocked domains. These settings are local configuration. Raw JSON export contains configuration including the filter-consent state; it is not a restorable settings backup.
- The user starts the proximity counter while in the resumed protection host. Ollo counts complete far-near-far cycles from the proximity sensor; it does not verify form or whether an exercise occurred. Users can instead report completion of their own task. Counts and earned access are volatile, use a monotonic fixed window, are limited to the same boot, and are lost on process restart. They are not backed up. No camera/microphone or body-sensor permission and no new SDK are added for this feature.
- Accessibility node retrieval is a separate, opt-in capability: only after separate Content filter consent and an enabled target filter, for target YouTube/Chrome windows, visible non-password nodes only, bounded to 512 nodes and depth 32. Only the visible Chrome URL bar and YouTube tab label text are read. Node attributes are transient, processed locally, and not stored or transmitted. Runtime events and `FLAG_REPORT_VIEW_IDS` are enabled only for opt-in filtering. Turning off consent clears filters.
- Observed YouTube matching is limited to the selected English Shorts tab in YouTube 19.17.42. Native Instagram is unsupported; Chrome Reels matching is limited to visible `/reel` and `/reels` paths. Chrome website rules use the visible, unfocused address field and do not block network traffic. Chrome-route and actual blocking behavior remain unverified; the AVD tree observation alone is not evidence of successful blocking.
- Settings backup is a strict schema-4 format importing schemas 1 through 4. It includes the new user configuration and optional filter preferences, but excludes installation-only Content filter consent (the current install's consent is preserved on restore), purchases, OS permissions, usage, timers, and volatile exercise state. The user previews/applies it; a chosen cloud document provider remains outside Ollo's storage control.
- Android activity/screen lifecycle events supplement summary buckets to estimate calendar-day usage; event data remains local. No new SDK, advertising identifier access, camera/microphone/body-sensor permission or Ollo server is introduced by these features. The app's existing RevenueCat network processing and permissions remain as described below.
- These are source/runtime facts for the testing preview, not completed Play Console answers. The 0.5.0 APK has not been accepted; no runtime claim is made for content-filter blocking. Exact candidate and test scopes are in [[PRODUCT-WORK-2026-10-20]]. The earlier no-SDK/no-restore statements below must not be submitted as current facts.

### Purchase services

- RevenueCat adds purchase-history processing off-device. A blanket no-data-collected answer is no longer supportable. Its [official Google Play guidance](https://www.revenuecat.com/docs/platform-resources/google-platform-resources/google-plays-data-safety) calls for purchase history, non-ephemeral processing and purchase-service purposes including analytics; review the live form and actual integrations before submission.
- Ollo uses an SDK-managed anonymous/pseudonymous customer ID. No app account, contact attributes, attribution collection calls, PostHog, Firebase or ad network are added. Removing AD_ID permission does not mean the purchase service has no identifiers.
- SDK setup and customer-info refresh run at startup/foreground, even if the user never taps Buy. Do not describe all SDK collection as optional paywall-only processing. Paywall interaction events also need configuration/source review; this whole-app worksheet is not settled by the core-SDK category table alone.
- Ollo does not pass selected packages, app-use history, rules, quiz answers or exports to RevenueCat. Those local/export flows retain the boundaries below. Manual cloud-provider exports remain a separate review question.
- Manifest permissions now include INTERNET, ACCESS_NETWORK_STATE and BILLING alongside usage/boot/signature permissions. AD_ID is explicitly removed. The merged debug package was inspected; production/minified/provider behavior remains separate acceptance.
- Local measurement deletion does not delete RevenueCat/store purchase records. Owner must supply a support/privacy contact and provider-deletion process. SDK purchase-data retention is not the32-day local usage cleanup.
- RevenueCat reports encrypted service transport. Do not generalize that statement to every user-selected document provider or untested SDK integration.
- All current features stay free during testing. Test Store simulates purchases; no real production sale, policy publication or Console filing was performed.

## Export boundary and account distinction

The document picker makes export a deliberate action and gives the user the destination choice, but it does not guarantee that the chosen destination is local. A local destination is on-device-only processing and is outside Play’s collection definition. A cloud-backed provider can receive and transmit the generated file; if the provider handoff means the app is transmitting this data off-device, the developer-facing guide’s collection definition applies and the export data should be declared as optional collection for App functionality. The user-initiated transfer exception likely means the same explicit export need not be declared as sharing when the user reasonably expects the chosen destination to receive the file. These are separate form answers. The file includes package names and usage information in CSV and more settings/baseline/outcome details in JSON. Treat the selected provider’s onward storage, sync, deletion and encryption as outside Ollo’s control. The user can cancel before choosing a destination; once saved, Ollo’s measurement-deletion action cannot retract that file.

Keep three concepts separate in all answers and user text: Android system permission access; Ollo’s local, accountless app state; and the developer’s Google Play Console/store account. Only the second is Ollo’s product data store in the current build. No app login or account deletion backend exists.

## Future variants — not current declarations

These are separate product choices and must be reviewed before adding code or updating Play answers:

- **RevenueCat / paid access:** adds purchase and entitlement processing. By default its SDK generates and caches an anonymous App User ID; CustomerInfo purchase/entitlement data is also cached on-device and may be served offline. This ordinary cached CustomerInfo path is distinct from RevenueCat’s separately named Offline Entitlements outage feature, which locally verifies store purchases while RevenueCat servers are unavailable. Do not infer that a cached, previously verified lifetime entitlement cannot work offline just because the separate Offline Entitlements feature has limitations. Decide whether the default anonymous identifier is acceptable, and map purchase/entitlement data, retention, deletion and provider terms before launch. Sources: [RevenueCat customer IDs](https://www.revenuecat.com/docs/customers/user-ids), [RevenueCat caching](https://www.revenuecat.com/docs/test-and-launch/debugging/caching), [RevenueCat CustomerInfo and Offline Entitlements](https://www.revenuecat.com/docs/customers/customer-info) (accessed 17 October 2026). No billing integration is present now.
- **PostHog / product analytics:** the SDK creates an anonymous pseudonymous `distinct_id`; PostHog says events have a distinct ID even when no person profile is created. Disabling person profiles therefore does not make stock SDK capture identifier-free. A zero-identifier aggregate count would need a custom architecture, not an assumption about SDK settings. If that strict constraint is required, reject any vendor mode that necessarily sends an identifier or events before opt-in. Sources: [PostHog identify users](https://posthog.com/docs/getting-started/identify-users), [PostHog people and distinct IDs](https://posthog.com/docs/data/persons) (accessed 17 October 2026). No PostHog integration is present now.
- **Firebase Crashlytics / reliability reporting:** Firebase documents Crashlytics Installation UUID, Firebase Installation ID, session ID, event timestamp, package/version, device metadata and stack traces among Crashlytics data. Consent controls do not by themselves make this identifier-free or mean no collection before/after user choice. Assess default collection behavior, data types, deletion/retention and disclosures before adding it. Source: [Firebase privacy and security](https://firebase.google.com/support/privacy/) (accessed 17 October 2026). No Firebase integration is present now.

Adding any of these requires a source and packaged dependency audit, updated privacy explanation and Data safety review; consent is not a substitute for accurately describing data that the chosen SDK collects.
